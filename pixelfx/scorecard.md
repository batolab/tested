# Public scorecard — pixelfx real test

Repo under test: patch-gg/pixelfx (version 0.3.0), https://github.com/patch-gg/pixelfx
Method: the repository was cloned and exercised with its own documented tools on Node.js. The effect count was verified three independent ways (the tool's own registry, the effect files on disk, the bundled catalog). A sample of effects across categories was rendered to animated GIFs, a sprite sheet was exported, one effect was re-rendered with a different palette, the repository's own checker was run on the sample and then on the full library, the documented programmatic API was run against a small sample scene, one move was rendered acted out with its target dummy, and the documented npm install was performed in a scratch project.
Claim check — "244 effects": CONFIRMED. Three independent counts (the tool's registry function `allIds()`, the effect files under `src/fx/` excluding shared `_lib.js` helpers, and the rows of `docs/CATALOG.md`) each give exactly 244 effects in 21 categories, and the per-category numbers agree across all three methods. The GitHub repository description said 232 at the time of an earlier scan; the author has since corrected it to 244. (The first commit message mentioned 299 effects.)
Results:
- Effect count: 244 in 21 categories by all three counting methods — matches the README claim.
- Install: clone-and-run works with no build step and zero runtime dependencies; `npm i github:patch-gg/pixelfx` in a scratch project succeeded.
- Rendering: 11 effects across 10 categories rendered to animated GIFs, 0 errors (fire/campfire, fire/torch, ice/frost-nova, explosions/big-explosion, lightning/plasma-ball, shadow/black-hole, weather/fireflies, critters/butterfly, ui/confetti, holy/heal, moves/sword-combo).
- Sprite sheet: ice/frost-nova exported as a transparent PNG sprite sheet (103 frames, 288×192 each, 9-column grid) plus Aseprite-style JSON with frame rectangles and metadata (fps 30, loop flag, pivot, per-frame act data).
- Palette swap: fire/torch re-rendered with a blue palette produced a blue flame with no code changes, as documented.
- The repository's own checker: sample of 11 effects — 11 pass, 0 fail, 1 warning ("slow: 4.9 ms a frame" on the largest explosion). Full library — 244 pass, 0 fail, 19 warnings, and every warning is a per-frame speed note (4.2–9.6 ms per frame), not a correctness failure.
- Programmatic API (createFrame / createFx / composite, as in the README): composed ice/frost-nova over a small hand-made sample scene and wrote out the composited frames.
- Acting: tools/act.mjs rendered moves/sword-combo as a character performing the combo on a target dummy (MP4, 266 frames).
Limitations (stated plainly): the repository is brand new (created 2026-10-30, 8 commits, version 0.3.0) and its headline number has already needed one correction (232 vs 244), so counts may drift again as effects are added or merged. Rendering and checking are not fast: the checker flagged 19 effects as slow, and the full-library check is a long run. Only 11 of the 244 effects were rendered and inspected individually; the rest are covered by the checker's automated pass/fail only. The bundled Claude Code skill for authoring new effects was NOT tested (it requires a Claude Code account). The hosted web gallery was not exercised. The exported sprite sheet was verified structurally (transparency, JSON fields) but not loaded into a game engine such as Godot or Unity. The gallery font (Patch Pixel, in gallery/fonts) is excluded from the MIT license per the repo's NOTICE file.
Files in this folder: the test instructions used; the count script and the API sample script (inputs); raw outputs — the exported sprite sheet (PNG + JSON) and the full checker output.
